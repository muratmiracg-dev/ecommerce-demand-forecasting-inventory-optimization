# Analytics Methodology

## 1. Objective

The project converts historical e-commerce signals into a 52-week demand plan
and SKU-level inventory decisions. It demonstrates how statistical forecasting,
machine learning, SQL, BI reporting, and inventory mathematics can operate as a
single management system.

## 2. Synthetic Data Design

The historical period covers 157 ISO weeks from 2023-01-02 to 2025-12-29.
The portfolio contains 60 SKUs across Dresses, Knitwear, Outerwear, Tops,
Bottoms, and Accessories. Weekly sales are generated by SKU and channel.

Demand incorporates:

- SKU base demand and growth trend
- Annual and category-specific seasonality
- Campaign and promotion uplift
- Channel mix
- Discount elasticity
- Product lifecycle
- Random demand variation
- Stock constraints and lost-sales estimation

The source generator uses a fixed seed (`20260726`) for reproducibility.

## 3. Forecast Candidate Models

### Seasonal Naive

Uses demand from the same ISO week in the prior year. It is a transparent,
seasonality-aware benchmark.

### 8-Week Moving Average

Uses a blended recent-demand signal to represent a simple operational forecast.
It reacts faster than the annual benchmark but may lag turning points.

### Gradient Boosting

Models non-linear relationships between demand and engineered calendar,
promotion, lag, rolling, trend, and product features.

## 4. Backtesting and Champion Selection

The latest 13 historical weeks are excluded from training and used as the
holdout set. Every candidate is evaluated per SKU with:

- **MAE:** average absolute unit error
- **RMSE:** error measure that penalizes larger misses
- **WAPE:** total absolute error divided by total actual demand
- **Bias:** signed error relative to actual demand

The candidate with the lowest SKU-level WAPE becomes the champion. The selected
model is then refitted using all historical observations and used to produce the
52-week forecast.

The model governance output retains all candidates, their metrics, rankings, and
champion flags. This makes the selection auditable instead of treating the model
as a black box.

## 5. Forecast Uncertainty

The project estimates residual standard deviation from backtest errors. Lower and
upper 80% bounds are generated around the point forecast. This uncertainty is
then reused by the inventory engine when calculating safety stock.

## 6. Inventory Mathematics

For each SKU and scenario:

```text
Lead-time weeks = lead-time days / 7
Safety stock = z(service level) × residual std × √(lead-time weeks)
Reorder point = average weekly demand × lead-time weeks + safety stock
Holding cost per unit = unit cost × 24%
EOQ = √(2 × annual demand × order cost / holding cost per unit)
Inventory position = ending on-hand + on-order
```

The recommended order quantity covers the reorder point and cycle stock, then:

1. Applies the minimum order quantity when an order is required.
2. Rounds upward to the SKU case pack.
3. Calculates the required inventory investment.
4. Classifies the SKU as `ORDER NOW`, `MONITOR`, `HEALTHY`, or
   `OVERSTOCK REVIEW`.

## 7. Planning Scenarios

| Scenario | Demand multiplier | Service-level change | Lead-time change |
|---|---:|---:|---:|
| Lean | 0.90 | -2 percentage points | 0 days |
| Base | 1.00 | none | 0 days |
| Growth | 1.15 | +1 percentage point | 0 days |
| Resilience | 1.05 | +2 percentage points | +14 days |

These scenarios distinguish a normal operating plan from capital-constrained,
upside-demand, and supply-disruption decisions.

## 8. Reporting Layer

Reporting tables aggregate results to monthly, category, SKU, supplier, and
scenario levels. The same analytical outputs feed:

- SQLite and SQL views
- A 10-page Power BI PBIP report
- A 15-sheet Excel scenario planner
- A 10-page vector PDF
- Turkish and English 20-slide PowerPoint decks

## 9. Validation Strategy

Validation is performed at multiple layers:

- Referential integrity and non-negative measures
- Demand balance and date coverage
- Forecast completeness
- Exactly one champion per SKU
- Finite model metrics
- Case-pack-compliant recommendations
- Non-negative inventory values
- Pytest business-rule tests
- PBIP entity/property validation
- Excel formula-error scanning
- PDF and PowerPoint render inspection

## 10. Production Extension

A production version would add source-system ingestion, orchestration, model
registry and monitoring, forecast overrides, user authorization, alerting,
purchase-order approval, actual-vs-forecast tracking, and scheduled Power BI
refresh.
